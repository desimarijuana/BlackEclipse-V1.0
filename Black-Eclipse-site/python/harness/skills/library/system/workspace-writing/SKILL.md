# Workspace Writing

## Purpose

Write durable workspace documents that explain intent and navigation rather than restating code.

## When to use

- A README, meeting note, SOP, or release note is requested.
- A project document needs updating.

## When not to use

- A formal DOCX/PDF deliverable.
- Code documentation that belongs in source comments.

## Procedure

1. Read the existing document and surrounding context.
2. Preserve the established structure and voice.
3. Write the missing intent, decisions, and navigation.
4. Check links and commands.
5. Report the exact file changed.

## Guardrails

- Never fabricate data, sources, prices, or dates. Missing data is `UNAVAILABLE`.
- Record the source and retrieval time for every factual value.
- Do not execute trades, move funds, or mutate external systems from this skill.
- Do not duplicate canonical docs.
- Do not delete history; mark stale content instead.

## Output

Return the file reference and outline.
