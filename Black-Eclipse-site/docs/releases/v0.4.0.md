# v0.4.0

**Status: source release for a single-operator, self-hosted install.** Tagged on
the merged `main` tree. This is the **harness core-integrity release**: it makes
the runtime inspectable, observable, safety-bounded and packageable, and turns
every scorecard dimension into a number measured from a run instead of a label.
It is not a new desktop feature release and does not change the install story.

## What landed

| Area | What changed |
|---|---|
| **Execution plane (C2)** | One tool-execution path with typed results, cancellation and resumable runs; the loop no longer grows a second executor. |
| **Tool economics (C3)** | Per-tool cost/latency accounting and budgets, so a run can be judged on work done rather than tokens spent. |
| **Goal / plan / evidence (C4)** | Runs carry an explicit goal, plan and evidence trail; the verifier checks the evidence, not the prose. |
| **Agent fabric (C5)** | Spawn, blackboard and synthesis give sub-agents one shared contract instead of ad-hoc handoffs. |
| **Safety envelope (C6)** | Profiles, token budgets, native backends and signing define what the runtime may do before a tool is called. |
| **Observability (C7)** | Step spans, SLO v2, a gate and a dashboard; the SLO probe is re-runnable (`npm run probe:slo`, `npm run gate:slo`). |
| **Evaluation (C8)** | A conformance gate with a fault matrix and golden trace, external adapters (SWE-bench Lite, GAIA, tau-bench, FinanceBench), a nine-task finance QA corpus, and scorecard dimensions generated from runs. |
| **Versioned core (C9)** | `harness.__version__` / `HARNESS_API_VERSION`, a built wheel, and a minimal JSON-RPC 2.0 ACP adapter (`initialize`, `session/new`, `session/prompt`, `session/cancel`, `shutdown`). |
| **Legal** | Risk ownership surfaced across the product (risk disclosure, acceptable use, automated-trading disclaimer). |
| **Desktop** | Cross-platform runtime verified on all three CI runners, payload leak guards (no DB, keys or nested `.black-eclipse`), branded runtimes, and release hardening. |

## Compatibility

- `package.json`, `pyproject.toml` and `harness.__version__` are aligned at
  `0.4.0`; `npm run release:check` fails if they drift.
- The Next.js front door and the HTTP contracts are unchanged. The Python
  harness gains the ACP adapter and the versioned public surface alongside the
  existing tool API.
- The desktop app still installs per-user and seeds its own database; no
  browser lane, no hosted service.

## Not included

- PyPI upload (the operator step; credentials never live in the repository).
- Docker (C4) remains an operator step by ADR-071.
- Any multi-user or hosted-service claim.
